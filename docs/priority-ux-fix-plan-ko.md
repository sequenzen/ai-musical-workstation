# StageWrite AI 우선 UX 수정 기획서

## 1. 수정 범위

이번 수정 라운드는 API 미연결로 생기는 `프롬프트 반영` 문제를 제외하고, 실제 화면 사용 중 창작 흐름을 끊는 UX와 버튼 표현 문제를 고친다.

제외 항목:

- 작가 요청 문장에서 무대, 주인공, 갈등, 장르를 자동 추출하는 기능
- 실제 OpenAI/음악/음성 provider 연결 품질
- 신규 결제, 계정, DB, 협업 백엔드

포함 항목:

- 페이지 전환 시 스크롤 위치 초기화
- 결과/히스토리 드로어 노출 방식 변경
- 넘버 타임라인 기능 라벨 정확도 개선
- 모바일 네비게이션 추가
- 음악적 성취감이 느껴지는 생성 완료 피드백
- 크레딧 차감 버튼 문구 개선
- 저장 상태와 저장 버튼 분리
- 대본 도구 아이콘 버튼의 시각적 의미 강화

## 2. 목표

사용자는 `작업실 -> 바이블 -> 넘버 -> 리딩/공유`를 오가며 다음 세 가지 감각을 받아야 한다.

1. 지금 어느 화면에 있는지 즉시 안다.
2. 버튼을 누른 뒤 결과는 확인되지만, 작업 흐름은 끊기지 않는다.
3. 음악/리딩 생성처럼 중요한 순간에는 작은 보상감이 있다.

## 3. 우선순위

| 우선순위 | 항목 | 이유 |
| --- | --- | --- |
| P0 | 페이지 전환 스크롤 초기화 | 화면 이동 후 중간 위치에서 시작하면 길을 잃는다 |
| P0 | 결과 드로어 기본 비노출 | 액션 후마다 화면이 덮여 창작 몰입이 끊긴다 |
| P0 | 크레딧 버튼 문구 | 비용 버튼은 오해가 없어야 한다 |
| P0 | 모바일 네비게이션 | 모바일에서 주요 화면 이동 수단이 부족하다 |
| P1 | 넘버 기능 라벨 정확도 | 뮤지컬 구조 신뢰도를 만든다 |
| P1 | 저장 상태/저장 버튼 분리 | 버튼 의미와 상태 의미가 섞여 있다 |
| P1 | 대본 도구 라벨 | 아이콘만으로는 기능을 바로 알기 어렵다 |
| P2 | 생성 완료 와우 포인트 | 제품 기억에 남는 순간을 만든다 |

## 4. 화면 설계 변경

## 4.1 페이지 전환 스크롤 위치

### 현재 문제

바이블, 넘버, 리딩/공유로 이동했을 때 이전 스크롤 위치가 남아 화면 중간에서 시작할 수 있다. 사용자는 새 페이지로 이동했다는 느낌을 받지 못하고, 섹션의 맥락을 놓친다.

### 수정 방향

페이지 네비게이션을 누르면 메인 작업 영역과 오른쪽 패널을 모두 상단으로 이동한다.

적용 대상:

- 좌측 네비게이션: 작업실, 바이블, 넘버, 리딩/공유
- 결과 히스토리의 `관련 화면 열기`
- 넘버의 `대본 위치 보기`
- 바이블의 `작업실로 보내기`
- 리딩/공유의 내보내기 후 관련 화면 이동

### 화면 규칙

- 페이지 전체는 새 화면의 hero 또는 첫 섹션부터 보여준다.
- 오른쪽 패널도 해당 화면의 첫 카드부터 보여준다.
- 단, `대본 위치 보기`처럼 특정 위치를 보여주는 의도적 이동은 예외로 둔다. 이 경우에는 이동 후 하단 알림에 “선택한 넘버 위치로 이동했습니다”를 표시한다.

### 완료 기준

- 작업실에서 스크롤을 내린 뒤 바이블을 누르면 바이블 상단 제목이 보인다.
- 넘버에서 스크롤을 내린 뒤 리딩/공유를 누르면 리딩/공유 상단 상태 카드가 보인다.
- 결과 히스토리에서 관련 화면을 눌러도 화면 중간에 떨어지지 않는다.

## 4.2 결과/히스토리 노출 방식

### 현재 문제

음악 생성, 전체 리딩 생성, 내보내기, 저장 같은 액션 후 결과 드로어가 자동으로 열리며 화면 절반을 덮는다. 기록성은 좋지만 작가의 다음 행동을 막는다.

### 수정 방향

결과 드로어는 사용자가 직접 열 때만 크게 보여준다. 액션 완료 후에는 작은 결과 토스트와 우상단 히스토리 배지만 갱신한다.

### 새 동작

성공 시:

- 화면 오른쪽 아래 또는 상단 근처에 3초 토스트 표시
- 예: `음악 생성 완료 · Opening: 민서의 첫 박자`
- 토스트 안에 `보기` 버튼 제공
- `보기`를 누르면 결과/히스토리 드로어 열기

실패 또는 차단 시:

- 작업을 이어가기 어려운 경우에만 드로어를 자동으로 연다.
- 예: 크레딧 부족, 권리 체크 미완료, provider 실패
- 단순 성공 로그는 자동으로 열지 않는다.

대기/queued 시:

- 작은 pending 토스트 표시
- 우상단 결과 버튼에 점 또는 숫자 배지 표시
- provider 작업 큐는 계정/설정 안에서 확인 가능하게 둔다.

### 화면 구성

우상단 버튼:

- 기존 `결과/히스토리 8` 유지
- 숫자는 최근 결과 수 또는 읽지 않은 결과 수로 표시
- 버튼을 누르면 드로어 열림

토스트:

- 제목: 액션 결과
- 보조문: 생성물 또는 다음 행동
- 버튼: `보기`, `닫기`

예시:

| 액션 | 토스트 문구 | 자동 드로어 |
| --- | --- | --- |
| 대본 초안 생성 | 대본 초안이 준비됐습니다 | 열지 않음 |
| 음악 생성 | 음악 데모가 준비됐습니다 | 열지 않음 |
| 전체 리딩 생성 | 전체 리딩 샘플이 준비됐습니다 | 열지 않음 |
| Markdown 생성 | Markdown 파일을 만들었습니다 | 열지 않음 |
| 크레딧 부족 | 음악 크레딧이 부족합니다 | 열기 |
| 권리 체크 미완료 | 권리 체크가 아직 완료되지 않았습니다 | 열기 |

### 완료 기준

- 음악 생성 후 오른쪽 작업 패널이 가려지지 않는다.
- 내보내기 후 리딩/공유 화면을 계속 볼 수 있다.
- 결과/히스토리 버튼을 누르면 이전처럼 전체 로그를 확인할 수 있다.

## 4.3 넘버 기능 라벨

### 현재 문제

넘버 타임라인에서 카드의 실제 제목은 Charm Song, Conflict Duet, Reprise인데 기능 라벨이 I Want Song처럼 잘못 보일 수 있다. 뮤지컬 구조를 설계하는 화면에서 이 오류는 신뢰도를 크게 떨어뜨린다.

### 수정 방향

넘버 카드에 `극적 기능` 값을 명시적으로 저장하거나, 제목에서 안정적으로 파싱해 표시한다.

권장 표시 순서:

1. `cue.dramaticFunction`이 있으면 그대로 사용
2. 없으면 제목 앞부분에서 `Opening`, `I Want Song`, `Charm Song`, `Conflict Duet`, `Reprise`, `11시 넘버`, `Finale` 추출
3. 그래도 없으면 fallback을 사용하되 `기능 미지정`으로 표시

### 화면 표시

현재:

- 카드 제목: `Charm Song: 해린의 선택`
- 기능 라벨: `I Want Song`

수정 후:

- 카드 제목: `Charm Song: 해린의 선택`
- 기능 라벨: `Charm Song`
- 보조 beat: `관계 압박`

### 완료 기준

- 각 넘버 카드의 기능 라벨이 제목과 일치한다.
- 큐 인스펙터 상단에도 같은 기능 라벨을 보여준다.
- `넘버 맵 다시 만들기` 후에도 라벨이 틀어지지 않는다.

## 4.4 모바일 네비게이션

### 현재 문제

모바일 폭에서는 좌측 사이드바가 사라지지만, 작업실/바이블/넘버/리딩으로 이동하는 대체 네비게이션이 충분히 보이지 않는다. 하단 입력창은 좋지만 화면 이동이 어렵다.

### 수정 방향

모바일 전용 하단 탭바를 추가한다. 모바일은 집필보다는 검토와 가벼운 수정이 중심이므로, 탭은 4개만 둔다.

탭 구성:

- 작업실
- 바이블
- 넘버
- 리딩

### 배치

```
┌────────────────────┐
│ Top Bar             │
│ Main Content        │
│                    │
│ Floating Composer   │
├────────────────────┤
│ 작업실 바이블 넘버 리딩 │
└────────────────────┘
```

### 동작 규칙

- 탭바는 화면 하단 고정
- 현재 화면 탭은 강조색으로 표시
- 모바일 입력창이 있을 때 탭바와 겹치지 않도록 하단 여백 추가
- `결과/히스토리`, `계정/설정`은 상단 바에 유지

### 모바일 화면별 우선 콘텐츠

| 탭 | 첫 화면에 보여줄 것 |
| --- | --- |
| 작업실 | 작가 요청 입력, 대본 요약, 러닝타임 |
| 바이블 | 로그라인, 시놉시스, 캐릭터 |
| 넘버 | 넘버 타임라인, 재생/상태 |
| 리딩 | 리딩 상태, 공유 링크, 코멘트 |

### 완료 기준

- 390px 폭에서 작업실, 바이블, 넘버, 리딩을 하단 탭으로 이동할 수 있다.
- 하단 입력창과 탭바가 겹치지 않는다.
- 탭 라벨이 잘리지 않는다.

## 4.5 생성 완료 와우 포인트

### 현재 문제

색감은 차분하고 작가용 책상 느낌이 좋지만, 음악/리딩이 생성됐을 때 뮤지컬 서비스다운 감정적 보상이 약하다.

### 수정 방향

큰 애니메이션보다 작업 흐름을 방해하지 않는 작은 무대적 피드백을 넣는다.

적용 순간:

- 음악 생성 완료
- 전체 리딩 생성 완료
- 리딩 ready 상태 진입
- 첫 넘버 재생 가능 상태 진입

### 시각 요소

음악 생성 완료:

- 큐 카드에 1.2초 동안 은은한 gold border pulse
- 파형 영역이 한 번 밝아짐
- 토스트 문구: `넘버 데모가 준비됐습니다`

리딩 생성 완료:

- 리딩 상태 카드에 `준비됨` 배지 강조
- 캐릭터 캐스팅 카드에 작은 check 표시
- 토스트 문구: `전체 리딩 샘플이 준비됐습니다`

주의:

- 화면 전체 confetti는 쓰지 않는다.
- 창작 도구의 차분함을 깨지 않는 선에서만 사용한다.
- 움직임은 1-2초 안에 끝난다.

### 완료 기준

- 사용자는 생성 완료를 시각적으로 바로 인지한다.
- 피드백이 다음 편집/재생 액션을 방해하지 않는다.

## 4.6 크레딧 버튼 문구

### 현재 문제

`음악 생성 -12`, `전체 리딩 생성 -24`는 할인처럼 보이거나 의미가 모호하다.

### 수정 방향

비용이 드는 액션은 `사용`이라는 단어로 명확히 표현한다.

문구 변경:

| 현재 | 수정 |
| --- | --- |
| 음악 생성 -12 | 음악 생성 · 12 credits 사용 |
| 전체 리딩 생성 -24 | 전체 리딩 생성 · 24 credits 사용 |
| 전체 리딩 다시 생성 | 다시 생성 · 24 credits 사용 |

잔액 정보:

- 버튼 주변 또는 카드 상단에 `잔여 208 credits` 표시
- 잔액 부족 시 버튼 disabled + `크레딧 부족` 문구

### 완료 기준

- 비용 차감 의미가 한눈에 보인다.
- 잔액 부족 상태에서 왜 버튼을 누를 수 없는지 보인다.

## 4.7 저장 상태와 저장 버튼 분리

### 현재 문제

`로컬 보관 중`은 상태처럼 보이지만 실제로는 저장 버튼이다. 사용자는 이 버튼을 눌러야 저장되는지, 이미 저장됐다는 뜻인지 헷갈릴 수 있다.

### 수정 방향

상단 바를 `상태 표시`와 `저장 액션`으로 분리한다.

수정안:

```
로컬 저장됨 11:42     [저장]
```

상태 텍스트:

- `로컬 저장됨 11:42`
- `변경사항 있음`
- `저장 중`
- `서버 동기화됨`

버튼:

- `저장`
- 아이콘은 disk/save
- 변경사항이 없으면 disabled 또는 secondary 상태

### 동작 규칙

- 대본, 설정, 바이블, 큐를 수정하면 상태가 `변경사항 있음`으로 바뀐다.
- 저장을 누르면 `저장 중`을 거쳐 `로컬 저장됨 HH:mm`으로 바뀐다.
- 자동 localStorage 저장은 유지하더라도, 명시적 저장 버튼은 심리적 안정감을 주는 용도로 둔다.

### 완료 기준

- 저장 상태와 저장 버튼이 시각적으로 구분된다.
- 저장 버튼을 눌렀을 때 결과 드로어가 자동으로 열리지 않는다.
- 저장 완료 토스트만 표시된다.

## 4.8 대본 도구 버튼 라벨

### 현재 문제

대본 도구는 아이콘 버튼으로만 보인다. 접근성 라벨은 있지만 화면상 의미를 즉시 파악하기 어렵다.

### 수정 방향

데스크톱에서는 아이콘과 짧은 텍스트를 함께 보여준다. 모바일에서는 공간상 아이콘만 유지하되 하단 탭/툴팁/aria-label을 유지한다.

문구:

| 기능 | 데스크톱 버튼 |
| --- | --- |
| AI 제안 | AI 제안 |
| 코멘트 | 코멘트 |
| 러닝타임 계산 | 러닝타임 |
| 리딩 모드 | 리딩 모드 |

배치:

- 대본 편집기 바로 위
- 버튼 그룹은 왼쪽 정렬
- 현재 활성 상태는 border와 배경색으로 표시

### 완료 기준

- 데스크톱에서 각 버튼의 의미가 텍스트로 보인다.
- 모바일에서 버튼 크기가 44px 이상 유지된다.
- 버튼 라벨이 줄바꿈되거나 잘리지 않는다.

## 5. 화면별 최종 형태

## 5.1 작업실

주요 변경:

- 상단 저장 영역을 `상태 + 저장 버튼`으로 분리
- 대본 도구 버튼에 텍스트 라벨 추가
- 결과는 토스트로 표시
- 페이지 진입 시 항상 상단부터 시작

핵심 경험:

작가는 글을 쓰고, 바로 초안을 만들고, 대본 위에서 AI 제안/코멘트/러닝타임을 확인한다. 결과 로그는 뒤에서 쌓이고, 화면을 덮지 않는다.

## 5.2 넘버

주요 변경:

- 기능 라벨 정확도 개선
- 음악 생성 버튼 문구를 credits 사용으로 변경
- 음악 생성 완료 시 큐 카드와 파형 영역에 짧은 강조 효과

핵심 경험:

작가는 대본 흐름에서 어떤 넘버가 어떤 극적 기능을 갖는지 신뢰할 수 있고, 생성 완료 순간에 “데모가 생겼다”는 보상을 느낀다.

## 5.3 리딩/공유

주요 변경:

- 전체 리딩 버튼 문구를 credits 사용으로 변경
- 리딩 준비 완료 시 상태 카드 강조
- 내보내기 후 결과 드로어 대신 토스트 표시
- 권리 체크 미완료처럼 막히는 액션만 드로어 자동 표시

핵심 경험:

작가는 리딩, 공유 링크, 코멘트, 권리 체크, 내보내기를 한 화면에서 처리하되, 버튼을 누를 때마다 흐름이 끊기지 않는다.

## 5.4 모바일

주요 변경:

- 하단 4탭 네비게이션 추가
- 모바일 입력창과 탭바가 겹치지 않게 여백 조정
- 모바일은 검토/감상/코멘트 중심으로 유지

핵심 경험:

모바일 사용자는 긴 편집을 하지 않아도 작품 상태, 넘버, 리딩, 코멘트를 빠르게 오갈 수 있다.

## 6. 구현 메모

### 상태/컴포넌트

- `Toast` 또는 `ResultToast` 컴포넌트 추가
- `MobileBottomNav` 컴포넌트 추가
- 저장 상태용 `saveState` 또는 `dirty` 상태 추가
- 결과 기록 함수의 `openResults` 기본값을 `false`로 변경
- 실패/차단 케이스만 `openResults: true` 유지

### 스크롤

- 메인 컨텐츠 wrapper와 오른쪽 inspector wrapper에 ref 추가
- `activePage` 변경 시 두 영역을 `scrollTop = 0`
- 의도적 위치 이동 함수는 예외 처리

### 넘버 기능 라벨

- `MusicCue`에 `dramaticFunction` 필드를 추가하는 방향이 가장 안정적
- 기존 데이터 호환을 위해 없을 때 파싱 fallback 유지

### 반응형

- 768px 이하에서 좌측 사이드바 숨김
- 768px 이하에서 `MobileBottomNav` 표시
- 하단 composer가 있을 때 `padding-bottom`을 탭바 높이만큼 추가

## 7. QA 체크리스트

데스크톱:

- 작업실, 바이블, 넘버, 리딩/공유 이동 시 항상 상단에서 시작한다.
- 음악 생성 후 결과 드로어가 자동으로 열리지 않는다.
- 리딩 생성 후 결과 드로어가 자동으로 열리지 않는다.
- 크레딧 부족/권리 체크 미완료는 드로어 또는 명확한 차단 안내가 보인다.
- 넘버 카드의 기능 라벨이 제목과 일치한다.
- 저장 상태와 저장 버튼이 분리되어 보인다.
- 대본 도구 버튼의 텍스트가 보인다.

모바일:

- 390px 폭에서 하단 탭바가 보인다.
- 하단 탭으로 작업실, 바이블, 넘버, 리딩을 이동할 수 있다.
- 모바일 입력창과 탭바가 겹치지 않는다.
- 긴 버튼 문구가 잘리지 않는다.

감성 피드백:

- 음악 생성 완료 시 큐 카드 또는 파형이 짧게 강조된다.
- 전체 리딩 생성 완료 시 리딩 상태 카드가 준비됨으로 강조된다.
- 효과가 과하거나 편집을 방해하지 않는다.

## 8. 개발 순서

1. 결과 드로어 자동 열림 정책 변경
2. 크레딧 버튼 문구 변경
3. 저장 상태와 저장 버튼 분리
4. 페이지 전환 스크롤 초기화
5. 넘버 기능 라벨 안정화
6. 대본 도구 버튼 라벨 추가
7. 모바일 하단 탭 네비게이션 추가
8. 음악/리딩 생성 완료 피드백 추가

이 순서가 좋은 이유는 사용 흐름을 가장 크게 끊는 문제부터 제거하고, 그 다음 신뢰도와 감성 품질을 올릴 수 있기 때문이다.
