# StageWrite AI UI 리뉴얼 기획서

## 1. 리뉴얼 목표

StageWrite AI는 `뮤지컬 작사가/극작가가 작품 개발을 끝까지 완성하게 돕는 AI 워크스테이션`이어야 한다.

현재 화면은 기능 구현 범위가 넓어졌지만, 창작자가 매일 쓰는 도구라기보다 기능 목록이 모두 노출된 운영 대시보드처럼 보인다. 리뉴얼의 목표는 기능을 줄이는 것이 아니라, 창작 몰입에 필요한 기능만 전면에 두고 운영/결제/상용화 기능은 적절한 깊이로 숨기는 것이다.

핵심 판단:

- 첫 화면은 마케팅 랜딩이 아니라 `작업실`이어야 한다.
- 메인 네비게이션은 창작 흐름 중심이어야 한다.
- 결제, 상용화 콘솔, 런칭 키트, 모바일 리뷰, 결과 센터는 메인 작업 동선을 방해하지 않아야 한다.
- 작가는 “AI가 뭘 할 수 있는지”보다 “내 작품이 지금 어디까지 왔는지”를 먼저 봐야 한다.

## 2. 타깃 정의

### 1차 타깃

창작 뮤지컬 작사가, 극작가, 작곡가와 함께 작업하는 작가, 공모전/워크숍을 준비하는 창작자.

이들은 긴 문서, 캐릭터, 장면 구조, 넘버 위치, 가사 프롬프트, 리딩 자료를 동시에 관리한다. 그래서 모바일 앱보다 노트북 웹 워크스테이션이 맞다.

### 2차 타깃

작곡가, 연출, 프로듀서, 배우 리딩 참여자.

이들은 전체 편집권보다 리뷰, 음악 데모 확인, 코멘트, 리딩 자료 확인이 중요하다.

### 지금 메인 화면에서 제외해야 할 타깃

서비스 운영자, 결제 관리자, 투자자/마케팅 페이지 방문자.

이들을 위한 기능은 필요하지만, 작가의 첫 화면에 보이면 안 된다.

## 3. 현재 화면 진단

### 좋은 점

- 뮤지컬 특화 기능이 있다: 스토리 바이블, 넘버 보관함, 음악 위치 추천, 리딩, 권리 체크.
- 주요 버튼은 대부분 동작하고 결과 센터까지 생겼다.
- 웹 우선 구조가 타깃 작업 방식에 맞다.
- 대본, 넘버, 리딩, 내보내기를 한 프로젝트 안에서 묶은 점은 강하다.

### 문제점

- 좌측 메뉴가 너무 많다.
- `상용화 콘솔`, `런칭 키트`, `모바일 리뷰`, `결제/크레딧`, `결과 센터`가 작가의 창작 흐름과 같은 레벨에 있다.
- 오른쪽 설정 패널이 길고, 작가가 처음 무엇부터 해야 하는지 약하다.
- 대본 편집 영역이 더 조용하고 넓어야 한다.
- 기능은 많지만 “다음에 무엇을 해야 하는지”가 화면이 먼저 말해주지 못한다.

## 4. 리뉴얼 후 정보 구조

### 메인 네비게이션은 4개만 둔다

1. `작업실`
2. `바이블`
3. `넘버`
4. `리딩/공유`

이 네 개가 창작자의 실제 흐름이다.

### 메인에서 숨길 항목

| 현재 항목 | 리뉴얼 처리 | 이유 |
| --- | --- | --- |
| 기획 보드 | `바이블` 상단 요약으로 병합 | 기획 보드는 독립 페이지보다 작품 바이블의 첫 섹션이 자연스럽다 |
| 내보내기 센터 | `리딩/공유` 안으로 병합 | 내보내기는 창작의 목적지가 아니라 공유/리딩의 하위 작업이다 |
| 결제/크레딧 | 우상단 계정 메뉴 또는 설정 모달로 이동 | 결제는 매일 쓰는 창작 기능이 아니다 |
| 상용화 콘솔 | 관리자/운영 설정으로 숨김 | 작가에게는 너무 이른 운영 정보다 |
| 런칭 키트 | 앱 밖 public marketing route로 분리 | 제품 내부 작업 화면에 마케팅 페이지가 있으면 맥락이 깨진다 |
| 모바일 리뷰 | `리딩/공유`의 공유 링크 카드로 병합 | 모바일은 보조 경험이지 독립 작업 모드가 아니다 |
| 결과 센터 | 우상단 알림/히스토리 드로어로 이동 | 결과 로그는 필요하지만 메인 목적지는 아니다 |

## 5. 전체 레이아웃

### 데스크톱 기준

권장 화면 기준: 1366px 이상 노트북.

```
┌─────────────────────────────────────────────────────────────┐
│ Top Bar: 프로젝트명 / 저장상태 / 히스토리 / 공유 / 계정       │
├──────────────┬──────────────────────────────┬───────────────┤
│ Left Nav     │ Main Canvas                  │ Right Panel    │
│ 4개 메뉴      │ 대본/바이블/넘버/리딩 본문     │ 조건/AI/큐 설정 │
└──────────────┴──────────────────────────────┴───────────────┘
```

권장 폭:

- 좌측 네비게이션: 220-248px
- 중앙 작업 영역: 남은 폭 전체
- 우측 패널: 340-380px, 접기 가능
- 상단 바: 56-64px

### 모바일 기준

모바일은 전체 집필용이 아니다.

모바일에서 제공할 것:

- 공유 링크 확인
- 음악 데모 감상
- 씬/넘버 코멘트 확인
- 간단한 코멘트 작성

모바일에서 제공하지 않을 것:

- 긴 대본 편집
- 전체 설정 마법사
- 결제/상용화 콘솔
- 복잡한 export 설정

## 6. 화면별 설계

## 6.1 작업실

작업실은 앱의 중심이다. 작가가 하루 중 가장 오래 머무는 화면이다.

### 구성

상단:

- 프로젝트 제목
- 저장 상태
- 버전 히스토리 아이콘
- 공유/내보내기 버튼
- 계정 메뉴

중앙:

- 작가 요청 입력 영역
- 대본 편집기
- 음악 위치 인라인 맵
- AI 제안/코멘트/러닝타임 결과 스트립

오른쪽:

- 처음에는 `생성 조건 마법사`
- 대본 생성 후에는 `AI 도우미`
- 음악 큐 선택 시에는 `큐 인스펙터`

### 버튼 배치와 이유

| 버튼 | 위치 | 이유 |
| --- | --- | --- |
| 대본 초안 생성 | 작가 요청 입력 영역 아래 | 입력과 결과가 직접 연결된다 |
| 음악 위치 크게 보기 | 대본 초안 생성 옆 보조 버튼 | 대본을 만든 뒤 자연스럽게 넘버 구조로 넘어간다 |
| AI 제안 | 대본 편집기 바로 위 툴바 | 대본을 읽으며 바로 적용할 수 있어야 한다 |
| 코멘트 | 대본 편집기 툴바 | 협업/검토는 대본 문맥 안에 있어야 한다 |
| 러닝타임 계산 | 대본 편집기 툴바 | 분량 판단은 편집 중 계속 필요하다 |
| 리딩 모드 | 대본 편집기 툴바 | 편집과 읽기 모드를 빠르게 전환해야 한다 |
| 저장 | 상단 바 | 프로젝트 레벨 액션이다 |
| 버전 저장 | 상단 히스토리 메뉴 | 매번 노출되기보다 저장 상태와 함께 있어야 한다 |
| 내보내기 | 상단 공유 메뉴 | 문서 산출은 작업 결과를 외부로 보내는 행위다 |

### 제거/숨김

- 작업실에서 결제, 상용화 콘솔, 런칭 키트는 보이지 않게 한다.
- 결과 센터는 우상단 알림 아이콘으로만 접근한다.

## 6.2 바이블

현재 `기획 보드`와 `스토리 바이블`을 병합한다.

### 구성

상단 요약:

- 제목
- 로그라인
- 핵심 갈등
- 목표 러닝타임
- 무대 규모
- 넘버 수

본문:

- 시놉시스
- 등장인물
- 구조
- 씬 카드
- 테마
- 레퍼런스/권리 기준

오른쪽:

- 바이블 갱신 조건
- 캐릭터/씬별 AI 제안

### 버튼 배치와 이유

| 버튼 | 위치 | 이유 |
| --- | --- | --- |
| 조건으로 바이블 갱신 | 바이블 상단 오른쪽 | 바이블 전체를 재구성하는 큰 액션이다 |
| 작업실로 보내기 | 바이블 상단 보조 버튼 | 구조를 확정하면 대본으로 돌아가야 한다 |
| 캐릭터 추가 | 등장인물 섹션 안 | 문맥 안에서 조작해야 한다 |
| 씬 카드 재배열 | 씬 카드 섹션 안 | 구조 편집 기능은 구조 영역에 있어야 한다 |

## 6.3 넘버

넘버 화면은 이 서비스의 차별화 핵심이다.

### 구성

상단:

- 목표 넘버 수
- 현재 넘버 수
- 음악 밀도
- 남은 음악 크레딧

본문:

- 대본 흐름 기준 타임라인
- Opening, I Want Song, Reprise, 11시 넘버, Finale 같은 극적 기능 표시
- 각 넘버의 위치, 의도, 가사 프롬프트, 스타일, 상태

오른쪽:

- 선택한 넘버의 큐 인스펙터
- 가사 프롬프트
- 모티프
- 금지/네거티브 프롬프트
- 음악 생성/재생

### 버튼 배치와 이유

| 버튼 | 위치 | 이유 |
| --- | --- | --- |
| 넘버 맵 다시 만들기 | 넘버 화면 상단 | 전체 음악 구조를 재구성하는 액션이다 |
| 큐 열기 | 각 넘버 카드 안 | 해당 넘버를 편집하기 위한 직접 액션이다 |
| 음악 생성 | 오른쪽 큐 인스펙터 하단 | 비용이 드는 액션이므로 상세 조건 확인 뒤 눌러야 한다 |
| 재생 | 음악 생성 옆 | 생성 결과 확인은 같은 문맥에 있어야 한다 |
| 대본 위치 보기 | 넘버 화면 보조 액션 | 음악은 대본 위치와 함께 봐야 한다 |

## 6.4 리딩/공유

`내보내기 센터`, `모바일 리뷰`, 일부 `결과 센터` 기능을 이 화면에 흡수한다.

### 구성

상단:

- 리딩 상태
- 캐스트 수
- 공유 링크
- 권리 체크 상태

본문:

- 캐릭터별 음성 캐스팅
- 전체 리딩 생성
- 모바일 리뷰 링크
- 코멘트 요약
- export 카드

오른쪽:

- 리딩 비용 예상
- 크레딧 잔액
- 권리 체크리스트

### 버튼 배치와 이유

| 버튼 | 위치 | 이유 |
| --- | --- | --- |
| 전체 리딩 생성 | 캐스팅 영역 아래 | 캐스팅을 보고 비용을 확인한 뒤 눌러야 한다 |
| 모바일 공유 링크 생성 | 공유 카드 안 | 공유 링크는 리딩/리뷰 목적과 연결된다 |
| Markdown/Fountain/K-Stage/Reading Packet 생성 | Export 카드 안 | 파일 생성은 공유 화면에서 처리한다 |
| 권리 확인 기록 | 권리 체크 카드 안 | 외부 공유 전에 확인해야 하는 단계다 |

## 7. 디자인 테마

### 테마 이름

`Quiet Theatre Desk`

무대의 감성과 작가 책상의 실용성을 섞는다. 화려한 AI SaaS 느낌이 아니라, 오래 머물 수 있는 조용한 창작 도구여야 한다.

### 컬러

| 역할 | 색감 | 의도 |
| --- | --- | --- |
| 배경 | 따뜻한 종이색, 아주 옅은 그린 그레이 | 긴 글을 읽어도 피곤하지 않게 |
| 본문 | 먹색에 가까운 짙은 그린 블랙 | 대본/문서의 신뢰감 |
| 주요 액션 | 깊은 극장 그린 | 전문 도구 느낌 |
| 음악/하이라이트 | 은은한 앰버 | 무대 조명과 넘버의 감정 |
| 위험/권리 경고 | 차분한 코랄/레드 | 과장하지 않고 주의를 줌 |
| 비활성 | 저채도 회색 | 기능보다 문서가 먼저 보이게 |

피해야 할 것:

- 과한 보라색 AI 그라데이션
- 마케팅 SaaS식 카드 과다
- 장식용 빛 번짐, 오브, 추상 배경
- 지나치게 둥근 버튼

### 타이포그래피

UI:

- 한국어 산세리프 기반
- 작고 단단한 라벨
- 버튼은 짧고 명령형

대본:

- 세리프 계열 또는 대본용 읽기 좋은 폰트
- 줄간격 넉넉하게
- 중앙 편집기는 종이처럼 보여야 한다

### 밀도

작가용 도구는 정보가 어느 정도 촘촘해야 한다. 너무 넓은 마케팅형 여백은 피한다. 대신 대본 편집기에는 충분한 여백을 준다.

## 8. 버튼 원칙

모든 버튼은 아래 셋 중 하나여야 한다.

1. 화면 이동
2. 현재 화면 안에서 결과 생성
3. 결과/히스토리 드로어에 기록

이 셋 중 어디에도 속하지 않는 버튼은 제거한다.

### 버튼 계층

Primary:

- 대본 초안 생성
- 넘버 맵 다시 만들기
- 음악 생성
- 전체 리딩 생성

Secondary:

- 바이블 보기
- 작업실로 이동
- 대본 위치 보기
- 공유 링크 생성
- 내보내기

Icon:

- 저장
- 히스토리
- 알림/결과
- 사이드바 접기

관리 버튼:

- checkout
- 서버 동기화
- provider retry
- 비용 한도

관리 버튼은 메인 창작 화면에 노출하지 않는다.

- 서버 동기화
- team invite 관리

위 기능은 필요 없다는 뜻이 아니다. 작가의 기본 작업 동선에서는 숨기고, `계정/설정/관리자` 안으로 넣는다.

### 앱 밖으로 분리할 기능

- 런칭 키트

런칭 키트는 public marketing page로 분리한다. 앱 내부에서는 작가가 작업 중이기 때문에 마케팅 메시지는 방해다.

## 11. 핵심 사용자 흐름

### Flow 1. 처음 쓰는 작가

1. 새 뮤지컬 클릭
2. 작업실 중앙에 “무엇을 쓰고 싶나요?” 입력
3. 오른쪽 생성 조건 마법사에서 장르/시간/레퍼런스/인물/넘버 수 입력
4. 대본 초안 생성
5. 바이블 자동 생성
6. 넘버 위치 추천
7. 첫 번째 넘버 편집/생성

### Flow 2. 대본을 다듬는 작가

1. 작업실에서 대본 읽기
2. AI 제안 클릭
3. 러닝타임 계산
4. 코멘트 추가
5. 버전 저장

### Flow 3. 작곡가와 협업

1. 넘버 화면 진입
2. 큐 선택
3. 가사 프롬프트/모티프/금지 프롬프트 수정
4. 음악 생성
5. 공유 링크 생성

### Flow 4. 워크숍 리딩 준비

1. 리딩/공유 화면 진입
2. 캐릭터별 음성 확인
3. 전체 리딩 생성
4. Reading Packet export
5. 모바일 리뷰 링크 공유

## 12. 빈 상태 설계

### 작업실 빈 상태

문구:

`한 문장만 적어도 됩니다. 장르와 러닝타임은 오른쪽에서 같이 정리할게요.`

버튼:

- 대본 초안 생성
- 샘플로 시작

### 바이블 빈 상태

문구:

`아직 작품 바이블이 없습니다. 작업실에서 초안을 만들면 자동으로 생성됩니다.`

버튼:

- 작업실로 이동
- 조건으로 바이블 생성

### 넘버 빈 상태

문구:

`대본의 감정 전환점이 보이면 넘버 위치를 추천할 수 있습니다.`

버튼:

- 음악 위치 추천

### 리딩/공유 빈 상태

문구:

`대본과 캐릭터가 준비되면 리딩 패킷과 공유 링크를 만들 수 있습니다.`

버튼:

- 캐릭터 확인
- Reading Packet 생성

## 13. 결과 피드백 구조

현재 결과 센터는 좋은 보강이지만, 메인 메뉴에 둘 필요는 없다.

리뉴얼 후:

- 결과 센터는 우상단 `결과` 아이콘 드로어로 이동
- 중요한 결과만 드로어에 남김
- 결과 카드에는 `관련 화면 열기` 버튼 유지
- 실패 결과는 재시도 버튼 포함

결과를 남겨야 하는 액션:

- 대본 생성
- 바이블 갱신
- 음악 생성
- 리딩 생성
- 내보내기
- checkout
- 초대
- 권리 확인
- provider polling/retry

결과를 남기지 않아도 되는 액션:

- 탭 전환
- 사이드바 접기
- 입력 필드 변경
- 단순 페이지 이동

## 14. 구현 우선순위

### Phase 1. 정보 구조 정리

- 좌측 메인 메뉴를 4개로 축소
- 기획 보드와 스토리 바이블 병합
- 내보내기 센터를 리딩/공유로 병합
- 결과 센터를 우상단 드로어로 이동
- 결제/상용화/런칭/모바일을 메인 메뉴에서 제거

### Phase 2. 작업실 몰입도 개선

- 대본 편집기 폭 확대
- 오른쪽 설정 패널을 단계형 마법사로 변경
- 대본 툴바 정리
- AI 제안과 러닝타임 결과를 더 읽기 쉽게 재배치

### Phase 3. 넘버 화면 강화

- 넘버를 카드 목록이 아니라 대본 타임라인으로 표현
- Opening/I Want/Reprise/11시 넘버를 극적 기능 태그로 표시
- 큐 인스펙터를 오른쪽에 고정

### Phase 4. 리딩/공유 화면 통합

- 리딩 생성, export, 모바일 공유, 권리 체크를 한 화면으로 묶기
- Reading Packet/K-Stage export를 더 전문적으로 보이게 만들기

### Phase 5. 디자인 정리

- 색상 토큰 정리
- 대본 편집기 typography 개선
- 카드 과다 제거
- 버튼 hierarchy 재정의

## 15. 성공 기준

리뉴얼 성공 여부는 아래 기준으로 판단한다.

- 처음 들어온 작가가 10초 안에 어디에 글을 입력해야 하는지 안다.
- 좌측 메뉴가 4개 이하로 줄어든다.
- 대본 편집 영역이 화면의 가장 큰 비중을 차지한다.
- 결제/운영/마케팅 기능이 창작 화면을 방해하지 않는다.
- 음악 큐가 단순 목록이 아니라 “뮤지컬 구조”로 보인다.
- 모든 비용 발생 액션은 실행 전에 비용과 권리 기준을 보여준다.
- 모든 액션 결과는 토스트 또는 결과 드로어에서 확인된다.
- 모바일은 집필 도구가 아니라 리뷰/감상 보조 도구로 제한된다.

## 16. 최종 제안

다음 구현은 기능 추가가 아니라 `덜어내기`가 중심이어야 한다.

가장 먼저 해야 할 일:

1. 좌측 메뉴를 `작업실 / 바이블 / 넘버 / 리딩·공유`로 줄인다.
2. `상용화 콘솔`, `런칭 키트`, `모바일 리뷰`, `결과 센터`, `결제/크레딧`을 메인 네비게이션에서 제거한다.
3. 결과 센터는 우상단 드로어로 옮긴다.
4. 작업실의 대본 편집기를 더 크게 만든다.
5. 오른쪽 패널을 긴 설정 폼에서 단계형 창작 마법사로 바꾼다.

이렇게 바꾸면 StageWrite AI는 기능이 많은 데모에서 벗어나, 실제 작가가 매일 열고 싶은 창작 도구에 가까워진다.
